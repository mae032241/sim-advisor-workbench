# 机制检查与设置落实

通用机制检查与拟用值落点检查供 CLI、MCP、托管 Agent 和 DSH 桥接共用。不需要因此重建资料库或向量；实际可用工具以当前服务目录为准。

## 规划流程

1. 用 `get_mechanism_checks({})` 查看目录，再通过 `mechanisms` 选择当前路线涉及的类别。
2. 结合任务和实际已读资料，将独立配置登记为原子设置，用 `check_ids` 关联检查问题。未知项保留 `unresolved` 及影响，不适用项保留理由。
3. 按原 ID 决定采用、调整或替代，在 `proposed_value` 中给出具体作用域、表达式、数值及单位，或配置条件。
4. 对已选且带有 `check_ids` 的设置填写 `implementation`，将拟用值完整原文保留在指定步骤字段。可放入一条 `inputs`，再于 `action` 说明操作。
5. 用 `review_plan` 查看机制遗漏、实施落点、阅读范围与结构问题，修订后保存。

一条通用温度输入的局部示例：

```json
{
  "proposed_value": "入口温度 T_in=300[K]，作用于命名入口选择。",
  "step_ids": ["boundaries"],
  "implementation": {"step_id": "boundaries", "field": "inputs"}
}
```

这是格式示例，不是推荐工况。完整设置行仍需 ID、状态、理由及相关来源字段；指定步骤的 `inputs` 应有一项包含拟用值完整文本。

## 检查范围

机制目录提供通用实施问题，Agent 仍需选择适用机制并检索来源。它不自动推导模型的完整方程组，不是案例答案或可引用证据。

检查器根据已登记的 `check_ids` 展开相关机制清单，提示尚未登记的问题。没有机制关联时报告覆盖未知，不自动视为齐全。

落点检查仅验证 `proposed_value` 原文保留在指定步骤的 `action`、单条 `inputs` 或单条 `checks` 中。摘要、引文原值或其他步骤不能替代指定落点。缺少必要落点或删除已有拟用值会被保存校验拒绝，草稿保留以便修复；较早设置表可省略新增字段。

文本保留不证明表达式正确、全部机制已被识别、引用足以支持拟用值或替代路线等价。未映射、未知和未决项继续作为审阅提示，不应为了通过保存而强行标为已采用。

## 接入

更新服务后，外部 DSH 会话需重新绑定以发现新工具；较早服务未提供该工具时，桥接仍按实际能力连接。详细字段见 [工具契约](tool-contract-transports.md)，设置表与阅读定位见 [案例导航](case-navigation.md)。
