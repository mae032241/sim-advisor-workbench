# 原始地址与建库的对照

本对照回答：相同资料是否经过预先解析、组织与索引，会不会改善 Agent 的方案质量和使用效率。它不是“有资料与无资料”的比较，也不以旧 QMD 检索组代替原始地址组。

## 两组输入

| 项目 | 原始地址组 | 建库组 |
| --- | --- | --- |
| 用户需求、初始几何 | 相同 | 相同 |
| 可见案例与文档原件 | 相同的原始文件或目录地址 | 相同地址 |
| 普通能力 | 列目录、搜索文件、读取、编码及按需解析原件 | 相同能力 |
| 预构造资料 | 不提供 | 增加已建库的概要、案例树、配置引用、手册章节树及检索工具 |
| 最终交付 | 相同方案格式 | 相同方案格式 |

原始地址组不提前生成摘要、方法卡、案例列表说明、章节树或可检索解析档案；Agent 自己在执行中选择怎样查找与解析。原件已有的官方目录、HTML 链接和配套教程可以使用，两组都保留。案例原件如果需要解析器或 COMSOL，两个组获得同样的运行环境；不能只给对照组不可读取的二进制文件。

如果为安全访问挂载资料，挂载层只限制可见原件，不做语义预处理、摘要或推荐。资源清单必须按独立规则确定，不能依据测试题向原始地址组或建库组挑出答案对应的案例。不能只对工具接口做隔离而让普通文件工具读到保留测试集、评分文件或历史答案。

## 保持一致

- 同一模型、推理设置、任务题面、初始几何、时间和上下文预算；每题使用新会话。
- 共用方案要求与普通工具说明。差异仅限建库工具的存在及其必要调用说明；不向任一组加入按题定制的路线提示。
- 方案保存格式一致。原始地址组允许以原文件路径与章节/节点定位引用，不能因缺少资料库来源 ID 被拒绝保存；建库组仍核实其工具引用是否真实读取。
- 原始地址组不得访问工作台的解析缓存、导航索引、QMD、旧测试输出或另一组的会话文件。建库组同样不得访问保留测试集原件和评分材料。
- 最多两个并行规划进程；记录是否共享热缓存，不能将模型耗时、建库耗时与检索耗时混为一个数。

## 记录与判断

沿用预先固定、独立保存的判断题，分别报告路线正确性、实施完整性与几何准备，不依据组别改变标准。评审先隐去组别，再对具体错误核查资料使用轨迹。

另记端到端时间、输入/输出 token、工具调用数、检索/读取/解析耗时、失败及是否保存方案。预先建库的时间和磁盘占用单独列出；多次使用时再讨论摊销。单次对照是小样本观察，不能把随机差异当成稳定提升。

质量持平而查找、解析成本下降也可以说明建库有价值；反之，调用次数增加或读到了更多资料不代表方案更好。若出现退化，应回到实际读写轨迹区分未找到资料、没有读取、理解错误和没有落实设置，不再用新增卡片数量代替效果。

## 当前状态

案例导航的小范围构造与接口验证不等于本消融已经执行。已有非方法卡/QMD 答案不能算作原始地址组。本协议确定后，应让实际插件 CLI 分别加载原始地址工具集和建库工具集，并先验证两组材料可见范围及保存入口，再开始模型推理。
